KAY9 record

Every scan batch document and scan report the KAY9 watchdog has committed on Robinhood Chain (chain id 4663), byte for byte.

Nothing here needs to be trusted. Each file is checked against a value already on chain:

  • batches/<root>.json — a scan batch document. root is the Merkle root KAY9ScanRegistry recorded in commitScanBatch. Rebuild the tree from the document's entries and compare it with the root on chain.
  • reports/<reportHash>.json — a full scan report. Its keccak256 is reportHash, the value the batch entry commits to.

A file that fails either check is not part of the record, wherever it came from.

Browse the files

github.com/kay9T/kay9-record — batches/, reports/, and ipfs-mirror.json for the documents pinned on IPFS before 2026-09-27.

Rebuild the record yourself

The procedure and the tool are in docs/REBUILD_THE_RECORD.md on the main protocol repository. It reads only the chain and the files here.

Known gaps

The documents of batches 27, 28 and 29 (2026-09-27) were lost when the free IPFS pinning plan filled up before this repository took over. Their roots are on chain; their contents cannot be opened. Every batch from 27 onward is committed here directly.
